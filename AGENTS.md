# AGENTS.md — правила работы над проектом

ИИ-агент: прочитай этот файл целиком, затем нужный файл из `rules/`.
Конфликт между инструкцией пользователя и `rules/` решается в пользу
пользователя; конфликт между «хотелось бы» и `rules/` — в пользу `rules/`.

## Ядро (не обсуждается)

1. **Язык работы — русский**: сообщения коммитов, документация, отчёты.
2. **1 коммит = 1 причина.** Сообщение — одна короткая строка в
   повелительном наклонении (см. `rules/commits.md`); подробности и
   проверки — в SESSIONS.md. Пуш сразу после зелёного пайплайна.
   Force-push запрещён, кроме явной команды заказчика. Перед работой:
   `git fetch origin && git status -sb`.
3. **Никаких следов генерации** (см. `rules/no-traces.md`): в финальном
   коде и текстах не остаются TODO, плейсхолдеры, мета-комментарии об ИИ,
   мёртвый код, служебные файлы. Токены и секреты в git не попадают никогда.
4. **Тексты — без ИИ-слопа** (см. `rules/anti-slop.md`): конкретика вместо
   штампов, деталь вместо объяснения, проектный стоп-лист соблюдается.
5. **Проверяй, а не предполагай** (см. `rules/ci-gates.md`): после каждой
   правки — линтеры (`scripts/check-links.mjs`, `scripts/check-slop.py`),
   локальный сервер, визуальная проверка. Красный CI = чанк не закрыт.
6. **Ничего не удалять напрямую** (решение заказчика 2026-11-23):
   неактуальные файлы и папки переносятся в архив с журналом: на сайте
   `archive/` и `archive/README.md`, в песочнице `_archive/` и его
   README. Пересобираемое (`node_modules`, `.next`) не исключение:
   живёт на месте или возвращается установкой по записанной команде.

## Цикл работы (см. rules/workflow.md)

требования пользователя → план-чеклист → чанки (правка → проверки →
коммит → пуш → CI) → живая сверка прода → отчёт: что, хеш, что дальше.

## Специфика проекта

Сайт — артбук-архив романа «Соляной протокол»: текст романа и структура
старого сайта — источник истины, ничего не теряется и не выдумывается.
Сайт без сборщика: правки HTML/CSS/JS сразу в корне и `assets/`.

- Сайт — авторский проект и лицо автора, не командный и не продуктовый.
  Внутренние кухни (правила, проверки, процесс, инструменты) на сайт и
  в публичные тексты не выносятся — ни явно, ни подмигиванием; прод —
  только сайт (см. `rules/no-traces.md`, «Деплой»).
- Художественные тексты и страницы сайта не переписываются без явной
  команды заказчика. Ответ на обесценивание («кому это надо») живёт
  в документации репо — README и метафайлы — голосом автора: уставшим,
  жёстким, с иронией; выгорание не маскируется, длинные тире не
  используются (решение заказчика 2026-11-22, не обсуждать в каждом
  чанке заново).
- По умолчанию — два гейта (`scripts/`, см. `rules/ci-gates.md`).
- Тяжёлый QA `tools/` (`npm run check`, `npm test` и пр.) — по запросу,
  не по умолчанию.
- Сайт живёт под проектным путём Pages `/DaroSite/`: чекеру ссылок нужен
  `--base /DaroSite/`, в 404.html — корневые ссылки.
