# Сайт «Соляной протокол»: рабочая документация

Версия: 0.1
Дата: 2026-10-24
Назначение: фиксировать структуру сайта, активную тему, состояние контента, бэкапы и проверки. При расхождении документа и кода правьте документ после кода, а не вместо него.

## 1. Главное правило

Активная тема сайта: киберпанк-нуар с неоном. Это решение пользователя, а не временный вариант.

Не заменять неон на бетон, соль, бумагу или другой «архивный» стиль без явного согласования. Спокойная бетонная тема лежит в `archive/themes/theme-salt.css` как архив, а не как активный стиль.

Неактуальные файлы не удаляются. Они переносятся в `C:\Site\archive\` и фиксируются в `archive/README.md`.

Соглашение по расширениям:

- `.js` в `assets/js/` это браузерные классические скрипты. Они подключаются через `<script src>`.
- `.mjs` в `tools/` это современные ES-модули Node.
- `.cjs` больше не используется. Старые версии лежат в `archive/tools/`.
- Сайт не требует Node для работы. Node нужен только для проверок и локального сервера.

## 3. Активная тема

- Палитра: тёмный синий, циан, лайм, розовый, хром, янтарный.
- Шрифт заголовков: `Unbounded`.
- Основной текст: `Literata`.
- Служебные подписи: `IBM Plex Mono`.
- Эффекты: неоновые линии, мягкое свечение, сетка, дождевые полосы, хром.
- Активный неоновый блок начинается в `main.css` с комментария `Пост-киберпанк: хром, лайм, электрический синий. 21.10`.

Архивная бетонная тема: `archive/themes/theme-salt.css`. Не подключать её к страницам без отдельного решения.

## 3.1. UI-эффекты

- Кнопка «Наверх» на всех страницах: создаётся через JS, слева внизу, 44 px, циановый гласморфизм, появляется после 400 px прокрутки.
- Медленный вертикальный скан по странице.
- Появление основных блоков при загрузке.
- Лёгкий параллакс обложки через CSS scroll timeline.
- Мягкие переходы между страницами через View Transitions.
- Проявление пластин галереи.
- Липкая шапка и липкий прогресс чтения с процентом.
- Подчёркивание пунктов меню неоновой линией.
- Подъём карточек и пластин при наведении.
- Пульсация номеров секций.
- Сканирующая полоса на изображениях при наведении.
- Все эффекты отключаются при `prefers-reduced-motion: reduce`.

### 3.2. Кнопка наверх

- Класс и id: `scroll-top-btn`.
- JS: `assets/js/chrome.js`, функция `initScrollToTop()`.
- CSS: `assets/css/main.css`.
- Иконка: локальный inline SVG chevron-up. Font Awesome не подключается.
- Позиция: слева внизу, 24 px на desktop и 16 px на mobile.
- Размер: 44 px.
- Появление: после `window.scrollY > 400`, класс `.visible`.
- Клик: плавный `scrollTo` наверх, с учётом `prefers-reduced-motion`.
- Кнопка создаётся через JS и работает на всех страницах. В HTML её нет.

## 6. Проверка

Все команды запускаются из `C:\Site`:

```powershell
npm run serve
npm run quick
npm run check
npm run qa
npm run mobile
npm run interactions
npm test
```

`npm run serve` поднимает локальный сервер на Node из `C:\Site`.
`npm run quick` делает быстрый smoke-тест пяти страниц на desktop и mobile. Использовать во время работы.
`npm run check` проверяет синтаксис, количество записей, главы, ссылки и наличие изображений.
`npm run qa` проверяет 18 маршрутов в desktop 1440x900 и mobile 390x844.
`npm run mobile` проверяет 18 маршрутов на 320, 360, 390, 430 и 768 px.
`npm run interactions` проверяет меню, поиск, фильтры, шрифт читалки, кнопку наверх и липкую шапку.
`npm test` запускает `check`, `qa`, `mobile` и `interactions` подряд.

QA проверяет:
- console errors;
- page errors;
- ответы 4xx и 5xx;
- битые изображения;
- внешние запросы;
- горизонтальный overflow.

Последний полный прогон: 36 проверок QA, 90 проверок мобильного адаптива, 11 интерактивных проверок, 0 ошибок.

Отдельная проверка `file:///C:/Site/characters.html`: 7 портретов, 0 битых, 0 ошибок консоли.

Проверка кнопки «Наверх»: на главной странице кнопка скрыта при загрузке, появляется после прокрутки, показывает прогресс и возвращает страницу к `scrollY = 0`.

Проверка чтения: на главе 1 липкая полоса прогресса остаётся под шапкой, процент меняется с `0%` до `60%` при прокрутке, параллакс обложки и проявление галереи включаются через CSS.

Инструменты описаны в `tools/README.md`. Для работы с проектом создан навык `solyanoy-site` в глобальных навыках OpenCode. Он напоминает про неоновую тему, Node-команды, мобильный адаптив и архив.

## 7. Правила правки

- `data.js` это источник данных. Не дублировать контент в HTML.
- После правки `data.js` проверять `node --check assets/js/data.js`.
- После правки `app.js` проверять `node --check assets/js/app.js`.
- Не добавлять внешние запросы, шрифты, аналитику и CDN.
- Не использовать длинное тире, эмодзи и рекламные обороты.
- Не удалять старые темы и бэкапы. Переносить в `archive/` с датой и записью в `archive/README.md`.
- Не менять активную тему без явного решения пользователя.
- Если меняется дизайн, сначала сделать бэкап `main.css`, потом правку, потом скриншот и проверку.

## 8. Git

- Репозиторий: `C:\Site\.git`.
- Ветка: `main`.
- Первый коммит: `0458045 Initial commit: site, assets, docs, archive`.
- `.gitignore` исключает временные файлы, кэши, логи, секреты, `.venv`, `node_modules`, `.opencode` и служебные папки редакторов.
- Ассеты, шрифты, шаблоны и документация остаются в репозитории.
- `archive/` остаётся на диске, но исключён из Git. Это локальная история версий.
- `.gitattributes` задаёт LF для текста и `binary` для WebP, шрифтов и растровых изображений.
- Локальные настройки: `core.autocrlf false`, `core.longpaths true`, `core.quotepath false`.

Основные команды:

```powershell
git status
git add .
git commit -m "Короткое описание правки"
git log --oneline --decorate -5
```

Не коммитить `.env`, локальные секреты, временные скрипты и папки кэшей. Если появляется новая категория временных файлов, сначала добавить её в `.gitignore`, потом проверять `git status`.
