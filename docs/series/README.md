# Пакет для серии из трёх книг

Версия: 0.1
Дата: 2026-10-22
Назначение: вести большую фантастическую серию так, чтобы к третьей книге не рассыпались мир, хронология, персонажи и обещания читателю.

## Когда нужен этот пакет

- У серии две или три книги, а не одна.
- Больше двух POV.
- Долгая хронология и несколько эпох.
- Сложная технология, магия или биология.
- Много фракций, локаций и второстепенных персонажей.
- Есть сквозная тайна или несколько тайн на несколько книг.
- Нужно контролировать, что читатель узнаёт в каждой книге.

## Что внутри

| Файл | Назначение |
|---|---|
| `series-bible.md` | Главный документ серии: обещание, дуга трёх книг, мир, фракции, каст, тайны, бюджет. |
| `book-bible.md` | Паспорт одной книги: вход, выход, акты, POV, новые правила, подсюжеты, проверка самостоятельности. |
| `chapter-plan-series.md` | План глав с привязкой к книге, POV, подсюжету и сквозной дуге. |
| `series-timeline.md` | Хронология серии: эпохи, даты, возраст, технологии, перемещения, знания. |
| `canon-ledger.md` | Реестр фактов и уровней канона, чтобы не спорить с собственной книгой. |
| `tech-system.md` | Правила технологии или магии: цена, предел, сбой, обнаружение, социальные последствия. |
| `setting-sheets.md` | Карточки планеты, вида и корабля или станции. |
| `pov-arc-tracker.md` | Баланс POV и арки персонажей на три книги. |
| `subplot-clue-tracker.md` | Подсюжеты, улики, тайны и открытые линии. |
| `name-registry.md` | Реестр имён и терминов, чтобы не плодить похожие названия. |
| `retcon-log.md` | Журнал изменений канона и порядок распространения правок. |
| `series-revision-checklist.md` | Проходы правок для серии, а не для одной главы. |
| `trilogy-dashboard.md` | Одна страница контроля: книги, слова, риски, обещания, следующие действия. |

## Порядок работы

1. Заполните `series-bible.md`. Это фундамент. Без него три книги будут тремя разными романами.
2. Соберите по одному `book-bible.md` на каждую книгу.
3. Сделайте `chapter-plan-series.md` для первой книги. Для второй и третьей достаточно верхнего уровня.
4. Заполните `series-timeline.md`. Не откладывайте на финал.
5. Заведите `canon-ledger.md` и `tech-system.md` до первой главы.
6. Заполните `pov-arc-tracker.md`, `subplot-clue-tracker.md` и `name-registry.md`.
7. Пишите первую книгу.
8. После первой книги обновите `retcon-log.md` и `trilogy-dashboard.md`.
9. Перед второй книгой проверьте вход и выход по `book-bible.md`.
10. Перед финалом серии пройдите `series-revision-checklist.md`.

## Правила серии

- Каждая книга имеет собственную цель, конфликт и финал.
- Серия не держится на одном герое, который не меняется.
- Новая технология не появляется только для финала.
- Новый персонаж не появляется только чтобы умереть.
- Тайна не открывается дважды.
- Если читатель может начать со второй книги и ничего не понять, вход плохой.
- Если читатель может пропустить вторую книгу и ничего не потерять, вторая книга плохая.
- Канон меняется только через `retcon-log.md`.
- Имя, термин и правило попадают в реестр до первого использования.
- Финал серии отвечает на главный вопрос, а не на последний вопрос.

## Связь с одиночными шаблонами

`docs/templates/` остаётся для карточек персонажей, локаций и фракций. Этот пакет не заменяет их, а добавляет уровень серии. Для одной книги достаточно старых шаблонов. Для трёх книг нужны оба набора.
