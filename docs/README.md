# Пакет документов для романа

Версия: 0.8
Дата: 2026-10-24
Назначение: держать мир, план, хронологию и правки в одном месте, чтобы сюжет не расползался по чатам и черновикам.

## Что внутри

- `templates/`: универсальные шаблоны для одной книги. Копируйте их в папку нового проекта и заполняйте.
- `series/`: шаблоны для серии из двух или трёх книг: библия серии, паспорт книги, хронология, канон, технологии, POV, подсюжеты, ретконы и пульт трилогии.
- `site/`: рабочая документация по сайту: структура, активная неоновая тема, состояние контента, бэкапы, QA и журнал изменений.
- `solyanoy-protocol/`: заполненный пример для романа «Соляной протокол». Его можно использовать как образец, но не как обязательный канон для другого проекта.

## Порядок работы

1. Скопируйте `templates/` в папку нового проекта.
2. Заполните `world-bible.md`. Без правил мира и главного конфликта остальные документы будут пустыми.
3. Соберите `chapter-plan.md` до начала черновика. План можно менять, но у каждой главы должна быть цель.
4. Ведите `chronology.md` после каждой главы. Не откладывайте на финал.
5. Пишите черновик.
6. Проходите `revision-checklist.md` по одному проходу. Не смешивайте структурную правку со стилистической.
7. Сверяйте текст со `style-guide.md` перед финальной вычиткой.
8. Обновляйте версию и дату в шапке каждого документа.

## Если книг несколько

Для серии из двух или трёх книг добавьте уровень `series/`. Порядок такой:

1. Заполните `series/series-bible.md`: главный вопрос, дуга книг, бюджет, фракции, каст, тайны.
2. Соберите по одному `series/book-bible.md` на каждую книгу.
3. Сделайте `series/chapter-plan-series.md` для первой книги.
4. Заполните `series/series-timeline.md` и `series/canon-ledger.md` до черновика.
5. Заведите `series/tech-system.md` и `series/setting-sheets.md` для фантастических элементов.
6. Ведите `series/pov-arc-tracker.md`, `series/subplot-clue-tracker.md` и `series/name-registry.md`.
7. После каждой книги обновляйте `series/retcon-log.md` и `series/trilogy-dashboard.md`.
8. Перед финалом проходите `series/series-revision-checklist.md`.

Для одной книги пакет `series/` не нужен. Он не заменяет `templates/`, а добавляет контроль серии.

## Правила

- Один источник истины. Если документ и черновик расходятся, сначала решите, что считать каноном, затем правьте оба.
- Неизвестное помечайте как `[ОТКРЫТО]`. Не заполняйте дыры догадками, которые потом станут каноном случайно.
- У каждого факта в библии должен быть ответ на вопрос «кто это знает и откуда».
- У каждой главы должна быть цель, препятствие и изменение. Если после главы ничего не изменилось, глава не нужна.
- У каждой улики должен быть вход и выход. Если улика не срабатывает, уберите её или сделайте ложной.
- Документы внутренние. Это не тексты для сайта и не маркетинговые материалы.
- Если проект попадёт в git, добавьте `docs/` в `.gitignore`. Это рабочие материалы, не часть публикации.
- В текстах не использовать длинное тире, эмотиконы и рекламные обороты.

## Как адаптировать под другой проект

- Замените название, жанр, объём и дату в шапке.
- Оставьте только те разделы, которые нужны вашему типу истории. Для повести хватит библии, плана и хронологии. Для цикла рассказов добавьте отдельный файл на каждый рассказ.
- Если мир небольшой, таблицы можно сократить до списков. Важна не форма, а ответы на вопросы.
- Если проект коллективный, добавьте в шапку владельца документа и правило согласования изменений.
