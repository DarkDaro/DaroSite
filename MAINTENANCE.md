# MAINTENANCE — обслуживание сайта «Соляной протокол»

Техническая часть: сервер, проверки, правки данных, звук, структура
репозитория, git. Публичное лицо проекта: `README.md`. Правила работы:
`AGENTS.md` и `rules/`. Метафайлы: `PROJECT-META.md` (паспорт),
`SESSIONS.md` (журнал), `BACKLOG.md` (задачи), `TECH-DEBT.md` (техдолг).

## Node и сервер

Сайт работает без Node. Node нужен только для проверок и локального
сервера:

```powershell
npm run serve
```

Затем открыть `http://127.0.0.1:8765/`.

## Данные и правки

`assets/js/data.js` это источник истины для контента. HTML-страницы содержат только оболочку, а тексты, досье, главы и галерея собираются из данных.

После правки проверяйте синтаксис:

```powershell
node --check assets/js/data.js
node --check assets/js/app.js
```

Основные правила:

- Не добавлять внешние запросы, CDN, аналитику и сторонние шрифты.
- Шрифты, изображения и поиск остаются локальными.
- Не использовать длинное тире, эмодзи и рекламные обороты.
- Активная тема сайта: киберпанк-нуар с неоном. Не заменять её на бетонную или бумажную без отдельного решения.
- Не удалять неактуальные файлы. Переносить их в `archive/` и фиксировать в `archive/README.md`.

## Звук

1. Откройте `about.html`, `http://127.0.0.1:8765/about.html` или нажмите «Настройки звука» в подвале.
2. Прокрутите до блока «Музыка, эффекты и озвучка».
3. Ползунок «Громкость» задаёт общий уровень музыки, эффектов и голоса. По умолчанию 70 процентов, значение запоминается.
4. Нажмите «Проверить музыку», «Проверить эффект», «Проверить голос». «Проверить музыку» начинает текущую тему с нуля, чтобы услышать интро.
5. Кнопка «Звук» в шапке выключает и включает всё сразу. Выбор запоминается.
6. В досье нажмите «Озвучить». В читалке кнопка скрыта, но код озвучки сохранён для будущей замены.

Темы длятся 48 секунд, начинаются и заканчиваются плавным фейдом, поэтому зацикливаются без клика. Пересборка: `npm run music`, нужен `ffmpeg` с `libmp3lame`.

Браузер не включает звук до первого клика. Если музыки не слышно, нажмите «Звук» в шапке или кликните по странице. Если голос звучит не по-русски, в Windows не установлен русский голос, и сайт использует системный.

## Печать питча: проверка

Проверка печати: Chromium print media, A4, 10 страниц, 0 ошибок. PDF лежит во временной папке проверки и в репозиторий не коммитится.

## Проверки

```powershell
npm run quick
npm run check
npm run qa
npm run mobile
npm run interactions
npm test
npm run clean
```

`npm run quick` нужен для быстрой проверки во время работы. `npm test` запускает полный набор перед коммитом.

`npm run clean` (tools/clean-chars.mjs) проверяет тексты и комментарии на иероглифы, символы полной ширины и невидимый мусор. Отчёт: выход 1, если находки есть. Чистка на месте: `npm run clean -- --fix`. Статусы задач (☐, ▶, ✅) и скобки плейсхолдеров из правил защищены whitelist.

Проверяется: console errors, page errors, ответы 4xx и 5xx, битые изображения, внешние запросы, горизонтальный overflow, мобильные ширины 320-768 px, тап-зоны и интерактив меню, поиска, галереи, читалки и звука. Последний полный прогон после карты и графа: 58 проверок QA, 155 мобильных проверок, 35 интерактивных проверок, 0 ошибок.

## Git и локальные папки

Рабочая ветка — `main`. Последний коммит: см. `git log -1`.

- `.gitignore` исключает временные файлы, кэши, секреты и служебные папки.
- `.gitattributes` задаёт LF для текста и `binary` для изображений, шрифтов и аудио.
- Ассеты, шрифты и публичные страницы остаются в репозитории.
- `docs/` остаётся на диске, но не входит в Git и не публикуется. Результаты аудита и исправленные расхождения хранятся локально в `docs/`.
- `archive/` остаётся на диске, но не попадает в Git. Это локальная история версий.
- `exports/` остаётся на диске, но не попадает в Git.

Внутренние материалы проекта ведутся локально в `docs/` и `archive/`. Они не публикуются на GitHub Pages и не входят в Git. В репозитории остаются публичные страницы, ассеты и технические инструменты сборки и проверки.
