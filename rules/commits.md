# Commits — стиль коммитов и git-дисциплина

История коммитов — журнал проекта. Одна строка на коммит: что сделано,
по-русски, в повелительном наклонении. Подробности, проверки и хеши
живут в SESSIONS.md, не в сообщении коммита.

---

## 1. Формат сообщения

```
<Глагол + что сделано>
```

- Одна короткая строка: «Добавить правила проекта», «Починить редирект»,
  «Убрать секцию», «Нормализовать OFL.txt».
- Язык русский, без точки в конце, без префиксов и перечислений.
- Детали, скрипты проверок и числа — в отчёт сессии (SESSIONS.md).

## 2. Дисциплина

1. **1 коммит = 1 причина.** Один фикс / одна страница / один раздел
   метафайла. Незапушенные коммиты не копить.
2. **Коммит → пуш → CI сразу.** Гейты перед коммитом (см.
   `ci-gates.md`); красный CI = чанк не закрыт.
3. **Force-push запрещён без явной команды автора.** Разошлась
   история — разобраться (fetch, log, diff), а не переписывать.
   Перепись истории (авторство, стиль) — только прямым приказом
   автора, со страховочной веткой и force-with-lease с явным
   ожидаемым SHA.
4. **Перед началом работы:** `git fetch origin && git status -sb &&
   git log --oneline -5`. Рабочая копия = зеркало GitHub; расхождение
   разбирается до правок, а не после.
5. **Правка только .md (метафайлы, правила)** — коммит сразу; CI
   дождаться, чанк закрыт после зелёного пайплайна.
6. **Автокоммиты инфраструктуры** (сообщение-UUID, «commit all») до
   пуша не доживают: `git reset --soft` + осмысленное сообщение.
7. Метафайлы обновляются тем же чанком, что и изменение, если оно
   меняет «почему так» (решение, отключение, рецепт отката).
